Recommend `cmd_record_review` wrap the `yaml.safe_load` in a try/except that reports "malformed YAML in reviews/<id>_review.yaml: <error>" — a reviewer whose findings contain natural free text (colons, quotes, code snippets) is exactly the case most likely to hit this, and a bare traceback is a bad UX for something that should be a routine, common failure mode.

Worth a `docs/experts/*` note or a coordinator-level convention (e.g. reviewers should always `lsof -i :<port>` before trusting a curl result, or use a scratch port).
